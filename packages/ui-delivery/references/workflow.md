# Shared workflow

1. Frame the task using relevant product instructions, components, audience, primary goal, and authorization. Done when the intended outcome and affected scope are explicit.
2. Select applicable rules and an adapter from inspected runtime facts. Assign an evidence method to each required check, including unavailable methods. Done when the proof plan fits the actual surface.
3. Shape material changes: identify what the user needs to decide or do, keep essential status and action discoverable, and organize secondary evidence around that task. Repeated empty report sections may deserve a consolidated status view while retaining each source's distinct pending, failed, partial, or unknown state. Preserve useful continuous reading and comparison; there is no universal page-height or scrolling cap. For a new app or materially new journey, start the browser collaboration loop in [interactive.md](interactive.md) by default. Reuse existing context for changed scope; honor explicit chat, autonomous or skip-onboarding requests. Consume submitted answers before dependent implementation. Done when hierarchy, navigation, states, and uncertain choices are reviewable; prototype only unresolved choices that matter.
4. Implement within the authorized mode, reusing compatible existing components. Review-only requests produce findings without product edits. Add dependencies only for concrete approved needs. Use [product-copy.md](product-copy.md) for substantial visible prose. Done when important affected behavior is exercisable, or limitations are recorded.
5. Verify the actual rendered result and realistic tasks using available tools. Keep failed, skipped, and unavailable results visible. Review a baseline's quality before treating similarity as useful evidence. Done when material issues are resolved or reported with artifacts and scope.
6. Retain only accepted decisions as product patterns, with owner, scope, rationale, and evidence. An agent's recommendation stays proposed. Return the runnable result and explain how submitted answers shaped it. Consume scoped feedback, complete authorized corrections without asking again, and return a fresh preview. During an active browser session, follow [live.md](live.md) and continue servicing the listener after acknowledging a result. Done with a review opportunity and receipt separating mechanical proof, design review, and human acceptance; live-session exit follows explicit pause/exit or demonstrated host disconnection.

Use the canonical [rules](rules.json) contextually. A source-backed advisory pattern may be unsuitable for a task; an adopted accessibility requirement remains a requirement. An exception documents a deviation and its remaining risk without converting a failure into a pass.
